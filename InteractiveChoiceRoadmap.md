# Interactive Choice — Roadmap

Plan for extending the interactive "choose a player" system. Written 2026-06-06, right after
shipping **Choose Someone to Drink** (the first interactive space).

## What already exists (the reusable machinery)

The whole pipeline is built and working for drink. Reuse it; don't rebuild it.

- **Pause/resume** — `RollDiceHelper.ProcessLandingEffects` intercepts an interactive space,
  sets master-local `waitingForChoice`, and `return`s before advancing. Resume is
  `RollDiceHelper.OnChooseResolved(targetIndex)`.
- **Client→master channel** — `PlayerChoiceRelay` (own GameObject, Manual sync). Ownership is
  pre-assigned to the current player each turn (`GameController.AssignChoiceRelayOwner`, called
  in NextPlayer/SamePlayerRollAgain/StartGame). Master resolves locally and never writes the
  synced counter (avoids the ownership-handoff serialize drop).
- **Prompt broadcast** — `GameController.StartChoosePrompt(mode)` sets `ChoosingPlayerIndex`,
  `ChooseMode`, bumps `ChoosePromptIncrement`, fires the landing popup (excluding the chooser
  via `PopupExcludePlayerIndex`), bumps `BoardVisualRefresh`, and shows the menu locally for
  master-as-chooser via `PlayerChoiceMenu.ShowForLocalChooser`.
- **Menu** — `PlayerChoiceMenu` (local UI, no sync). `CheckPrompt` (remote) / `ShowForLocalChooser`
  (master). `PopulateButtons` filters to Connected (status 0) non-self players, live every frame.
  64-button pool generated by `Assets/Editor/GenerateChoiceMenu.cs` + `PopulateChoiceMenuButtons.cs`.
  Head-placed, draining timer bar, `ChooseMode`-aware title.
- **Resolve + notify** — `GameController.ResolveChooseDrink(targetIndex)`: validates target
  (random fallback via `PickRandomOtherPlayer` on -1/invalid), logs, global popup, targeted drink
  cue (`ChosenDrinkPlayerIndex` + `ToggleChosenDrink`, mirrors LeaderDrink in `ToggleGameAudio`),
  then `NextPlayer`.
- **Timeout** — 30s master-side in `RollDiceHelper.Update` (`choiceTimeout`), resolves with -1.
- **Visual-only board refresh** — `GameVariables.RefreshBoardVisualsOnly` (piece + outline +
  cameras WITHOUT arming the dice timer), triggered by the `BoardVisualRefresh` synced counter.

`ChooseMode` is already plumbed: 0 = drink, 1 = swap, 2 = host (reserved). Menu title already
switches on it.

## Feature A: Choose Someone to Swap (mode 1) — the easy one

Reuses everything above. ~A `ResolveChooseSwap` twin plus a new space type.

1. **New space type `chooseSwap`** — `SpaceSettings.cs` bool flag; `UpdateBoard.cs` (`ApplyEffect`,
   `ReturnTextBasedOffSetting`, `ReturnMaterialBasedOffSetting`, the reset block); if it can be a
   mystery, `MysteryManager` (`ApplyMysteryResult` + reset block, `GetTextForType`,
   `GetMaterialForType`). See `.claude/skills/new-board-space`.
2. **Intercept** — in `ProcessLandingEffects`, add `if (spaceSetting.ChooseSwap) { waitingForChoice
   = true; choiceTimer = 0; gameController.StartChoosePrompt(1); return; }` (mode 1).
3. **Branch the resolve** — `RollDiceHelper.OnChooseResolved` currently always calls
   `ResolveChooseDrink`. Make it branch on `gameVariables.ChooseMode`: 0→drink, 1→swap.
4. **`GameController.ResolveChooseSwap(targetIndex)`** — validate target (reuse
   `PickRandomOtherPlayer`), swap `playerSpaceDataList[chooser]` <-> `playerSpaceDataList[target]`
   (reuse the swap math in `ProcessLandingEffects`), log "X swapped with Y!", global popup,
   swap audio (reuse SwapWithFirst/Last toggles or add one), then `NextPlayer`.
   - **Decision:** MVP = swap then advance (don't re-process the landed-on space's effect). The
     deterministic swap loops; matching that from a resolve callback is extra work — defer.
5. Menu/title/timeout/relay all work unchanged. Self already excluded.

**Effort: low.** This is the natural next build.

## Feature B: Host selection + Drink-With-Host notification (mode 2)

At game start the **master** picks a player to be the Host; every Drink-With-Host space then
notifies that Host. Two differences from drink/swap: the **chooser is master** (not the current
player) and the **trigger is game start** (not a landing).

### Generalizations needed first
- **Chooser index** — `StartChoosePrompt(mode)` hardcodes `ChoosingPlayerIndex = CurrentPlayerIndex`.
  Add `StartChoosePrompt(mode, chooserIndex)` (drink/swap pass CurrentPlayerIndex; host passes
  master's player-list index). Master choosing always uses the relay's master-direct path
  (`SubmitChoice` isMaster → resolve), so relay ownership doesn't matter for host.
- **Eligibility** — `PopulateButtons` excludes self. For host (mode 2) **include self** (master
  may pick themselves). Make the self-exclusion mode-aware.
- **Resolve branch** — extend `OnChooseResolved` to 2→host.

### Host flow
1. **`HostPlayerIndex`** — new synced int in `GameVariables` (default -1).
2. **Trigger at start** — in `GameController.StartGame` (master), after players/`CurrentPlayerIndex`
   are set, call `StartChoosePrompt(2, masterIndex)`. **Decision:** non-blocking MVP — let turns
   proceed; if no Host is set when a Drink-With-Host space hits, default to master or player 0.
   (Hard-blocking the first roll until Host is chosen is cleaner but more wiring — defer.)
3. **`GameController.ResolveChooseHost(targetIndex)`** — set `HostPlayerIndex`, log "X is the Host!",
   global popup. No NextPlayer (this isn't a turn).
4. **Notify on Drink-With-Host** — in `ProcessAudio`/`ProcessPopup`, when `DrinkWithHost`, in
   addition to the existing roller cue (`ToggleDrinkWithHost`), notify the Host: add
   `HostDrinkPlayerIndex = HostPlayerIndex; ToggleHostDrink++` and a popup targeted at the Host
   ("You're drinking with {roller}!"). Mirror the LeaderDrink block in `ToggleGameAudio`
   (`if (HostDrinkPlayerIndex == selfIndex) ToggleGameObject(Drink)`), including the tmp resets in
   all three init spots.
5. **Host leaves** — if the Host disconnects/leaves mid-game, either re-trigger host selection or
   fall back to master. Handle in `PlayerList.OnPlayerLeft`.

**Effort: medium** — mostly the chooser-index + eligibility generalizations and the host-drink
notification (a LeaderDrink copy).

## Cleanup / tech debt
- **Strip debug logs** once both features are verified: `[Relay]` (PlayerChoiceRelay), `[ChoiceMenu]`
  (PlayerChoiceMenu), `[PopupHUD]` (SpacePopupHUD), and `UPDATE OUTLINE SPACE` / previous-player
  logs in `UpdateSpaces.UpdateOutlineSpaces`.
- **`UpdateOutlineSpaces` line ~79** dereferences `playerSpaceDataList[PreviousPlayerIndex]` in a
  Debug.Log without a -1 guard — would throw for a spectator (selfIndex/Previous = -1). Guard it
  when touching that method.
- **Landing popup** currently targets everyone-except-chooser; revisit text/targeting per feature.

## Test checklist (per feature, 3 ClientSim clients)
Master-as-chooser AND client-as-chooser both resolve; everyone sees the right log/popup; the
target gets the cue; turn advances; 30s timeout falls back; roster change mid-choice updates the
menu; board outline (red on roller's space) updates for master + clients at prompt.
